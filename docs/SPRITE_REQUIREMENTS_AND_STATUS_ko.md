# 스프라이트·애니메이션 요구사항과 진행 상황

기록일: 2026-10-22. 기준 구현은 `codex/design-first-sprites`의 [`6d85dff`](https://github.com/jungducknam/pixelwright/commit/6d85dfffa7d5712967536fd5f9a594ed260c021f)이며, main `1899f66`을 통합했습니다. [PR #10](https://github.com/jungducknam/pixelwright/pull/10)은 초안·미머지 상태입니다. 이 문서는 사용자와 합의한 방향, 현재 증거, 남은 작업을 함께 관리합니다.

추적 이슈: [#12 — 스프라이트 생성 요구사항·진행 현황 및 보행 품질 개선](https://github.com/jungducknam/pixelwright/issues/12). 아래의 미완료 작업과 승인 조건을 이 이슈에서 추적합니다.

**현재 결론: 2D 시안 우선 생성과 픽셀·골격 검증은 구현했지만, 자연스러운 애니메이션과 완성 에셋 품질은 아직 달성하지 못했습니다.** 사용자는 현재 걷기 GIF의 부자연스러움을 지적했고, 프레임 검토에서도 접지·체중 이동·동작 연결 문제가 확인됐습니다. 이 후속 검토는 기존의 개별 포즈 검사와 별도입니다.

## 1. 목표와 생성 순서

스프라이트 시트와 걷기·공격·막기 애니메이션을 실제 이미지 생성 서비스로 만들고, 도트 규격·캐릭터 일관성·포즈·움직임을 검증합니다.

```text
참고 이미지 또는 프롬프트
  → 2D 도트 시안 생성·선택
  → 시안에서 신체 비율·관절·장비 연결 위치 관찰
  → 해당 비율의 맨 3D 골격과 카메라·동작 작성
  → 골격 애니메이션의 움직임 검토
  → 선택한 시안 + 골격 구도로 새로운 2D 상태 시트 생성
  → 픽셀·포즈·부위 크기·시간에 따른 움직임 검사
  → GIF와 실제 격자를 확인하고 작화 검토 기록
```

외형과 작화의 기준은 선택한 2D 시안입니다. 3D는 구도·카메라·관절·깊이·가림 관계를 전달합니다. 골격 검토 단계를 이미지 생성 전에 통과시키는 절차와 보행 검사는 후속 구현 대상입니다.

## 2. 요구사항

| ID | 요구사항 | 수락 기준 |
| --- | --- | --- |
| R01 | 참고 이미지나 프롬프트로 2D 도트 시안을 먼저 선택한다. | 첫 시안 생성에 3D 외형을 입력하지 않고, 이후 모든 상태가 같은 시안을 참조한다. 시안 선택과 작화 승인은 구분해 기록한다. |
| R02 | 시안에 맞춘 맨 3D 골격을 사용한다. | 관절과 작성한 깊이에서 신체 비율을 정하고, 실제 Blender 골격의 뼈 길이·카메라 투영을 검증한다. 권장 경로의 외형 메시 수는 0개다. |
| R03 | 구도에 맞는 새로운 2D 애니메이션을 그린다. | 3D 갑옷·재질·실루엣을 그대로 전사하지 않는다. 의복·장식·윤곽·명암은 2D 시안을 유지하며 동작에 맞게 새로 그린다. |
| R04 | 캐릭터와 부위·장비의 크기를 일관되게 유지한다. | 같은 카메라·배율·슬롯 크기를 사용하고, 신체와 장비의 고유 크기를 유지한다. 회전·가림·원근 단축은 구분해서 관찰한다. 동작 프레임별 확대·축소·중심 맞추기로 실패를 감추지 않는다. |
| R05 | 도트 품질을 준수한다. | 선언한 정사각형 셀, 셀 내부의 정확한 단일 RGBA, 정수 배율, 공통 팔레트, 알파 규칙을 통과한다. 윤곽 계단·색 뭉침·명암·가독성·불필요한 노이즈는 별도로 눈으로 검토한다. |
| R06 | 공유 시안과 상태별 스프라이트 시트를 사용한다. | sprite-gen에서 참고한 공유 캐릭터·고정 슬롯·상태별 시트·공통 격자와 팔레트를 적용한다. 걷기·공격·막기를 같은 캐릭터의 동작으로 읽을 수 있어야 한다. |
| R07 | 걷기 자체가 자연스럽다. | 좌우 접지·하중을 받는 자세·다리가 교차하는 자세가 이어지고, 골반·상체·장비가 보행과 연동된다. 발 미끄러짐·지면 관통·반복 경계의 튐을 검토한다. |
| R08 | 공격·막기의 의도와 무게감이 읽힌다. | 공격의 준비·타격·회복, 막기의 준비·버팀·복귀가 이어지고 손과 장비의 연결이 유지된다. 공격·막기는 실행 명세에서 일회 동작으로 취급한다. |
| R09 | 생성된 그림을 독립적으로 검사한다. | 실제 그림의 관절과 측정 가능한 치수를 관찰해 원본·계약 해시와 묶는다. 가려지거나 관찰하지 못한 항목은 REVIEW다. 골격 좌표 복사나 가까운 뼈에 픽셀을 배정하는 방식으로 그림을 합격시키지 않는다. |
| R10 | 결과와 실패를 재현할 수 있다. | 원본·선택 시안·계약·프롬프트·입력 해시·변환·GIF·검사 기록을 보존한다. 재생성 시 교체 원본과 이전 생성 기록을 남기고 새 그림을 다시 관찰한다. |

sprite-gen에서 참고한 범위와 고정 소스 링크는 [제작 절차](SPRITE_3D_ko.md#sprite-gen에서-참고한-점)에 기록했습니다.

### 현재 예제의 고정 규격

- 네이티브 프레임 128×128, 상태별 3열×2행의 6프레임, 최종 확대 PNG의 셀 4×4.
- 전체 네이티브 시트 768×384, 확대 PNG 3072×1536, 공통 가시 색상 24개, 이진 알파와 정확한 투명 RGBA.
- 월드 뼈 길이 허용치 `1e-6 m`, 관찰한 그림 관절의 목표 오차 최대 5셀, 측정 부위 치수 차이 최대 15%.

위 값은 **현재 실행에 고정한 계약**입니다. 향후 모션의 프레임 수·시간·접지 오차 기준은 설계 단계에서 정하고 생성 전에 기록합니다. 현재 6프레임이 최종 품질 요건이라는 의미는 아닙니다. 실패 후 허용치를 바꿔 통과시키지 않습니다.

### 걷기: 2026-10-22 후속 검토

사용자는 걷기가 부자연스럽다고 지적했습니다. GIF의 여섯 프레임과 보행 골격 코드를 살펴본 결과를 아래에 기록합니다. 시각적인 관찰과 원인 추정은 기존 숫자 검사와 구분합니다.

| ID | 관찰한 문제 | 근거·해석과 보완 방향 |
| --- | --- | --- |
| W01 | 상체를 고정하고 다리 자세만 교체하는 느낌 | 수동 관찰의 골반 좌표는 6프레임 모두 `(64, 65)`이며 약 1셀의 측정 오차가 있다. 골격의 걷기에도 골반 회전·좌우 체중 이동 설계가 부족하다. 지지하는 발에 따른 하중 이동을 먼저 설계한다. |
| W02 | 디딤·밀어내기가 흐리고 발이 미끄러지는 듯함 | 접지와 공중 복귀가 그림에서 명확히 읽히지 않는다. 실제 미끄럼 오차를 수치로 측정한 상태는 아니다. 보행 속도와 좌표계를 정하고 접지 구간·발 궤적·지면 높이를 검증해야 한다. |
| W03 | 인접 포즈와 마지막→처음의 연결이 어색함 | 앞쪽 프레임의 변화가 작다가 다리 자세가 바뀌며 반복 경계도 매끄럽지 않다. 시간 간격을 반영한 관절·발의 변위와 속도 변화를 전체 주기에서 검사한다. |
| W04 | 팔·방패·메이스의 무게감이 약함 | 골반·가슴·팔·장비가 하중 이동과 충분히 연동되지 않는다는 시각 판단이다. 장비를 든 보행에 맞는 제한된 흔들림과 손의 연결을 설계한다. |

기존 `walk` 개별 포즈 검사는 5 FAIL / 1 PASS입니다. **그중 한 프레임이 PASS라는 사실은 걷기 주기 전체의 자연스러움을 의미하지 않습니다.** 현재 검사는 픽셀 규격·뼈 길이·개별 좌표·일부 치수에 집중돼 있고 시간에 따른 동작 품질을 충분히 판정하지 못합니다.

기존 [작화 검토](examples/knight-design-first/art-review.json)의 걷기 재생성 지시는 당시의 고정 포즈를 전제로 한 기록입니다. 이번 피드백을 반영한 후속 작업에서는 **새 실행에서 보행 골격 자체를 먼저 수정·검토한 뒤** 그 계약에 맞는 그림을 생성합니다. 기존 원본과 계약은 이력으로 보존합니다.

### 공격·막기: 이미 확인된 결함

- 공격 3번: 메이스 머리가 기준 약 10셀에서 약 14셀로 확대됨.
- 공격 4번: 골격 목표보다 깊게 웅크림.
- 막기 1·3·5번: 방패 윗부분 높이가 목표에서 벗어남.
- 가려진 목·골반·투구 일부는 관찰 불가로 REVIEW. 번호는 0부터 시작하며 수동 관찰 오차는 약 1셀이다.

## 5. 후속 작업과 완료 기준

아래 항목은 아직 완료되지 않은 작업입니다. 이번 문서화로 구현되거나 해결된 것으로 처리하지 않습니다.

### P0. 골격 단계에서 자연스러운 걷기 만들기

- [ ] 걷는 방향·속도·제자리/이동 모드와 프레임별 시간을 정한다.
- [ ] 좌우 접지 → 하중을 받는 자세 → 다리가 교차하는 자세 → 반대발 접지의 주기를 설계한다.
- [ ] 골반·가슴·팔과 방패·메이스를 하중 이동에 연동한다.
- [ ] 발 접지와 지면 관통, 관절·발 궤적, 반복 경계의 연속성을 검사한다.
- [ ] 맨 골격 GIF를 보통 속도·느린 속도·프레임별로 검토하고 기준을 고정한 뒤 이미지 생성에 사용한다.

제자리 걷기에서는 화면상의 발 위치를 그대로 고정시키는 검사를 쓰지 않습니다. 선언한 루트 이동량을 복원한 좌표계에서 지지 발의 미끄럼을 검사해야 합니다. 접지·속도·연속성의 구체적인 수치 기준은 새 모션 계약을 만들 때 사전 결정할 설계 항목입니다.

### P1. 시안을 유지한 2D 재생성과 부위 일관성

- [ ] 선택한 기사 시안의 외형을 유지하고 새로 검토한 걷기 골격으로 상태 시트를 생성한다.
- [ ] 공격 3·4번, 막기 1·3·5번의 알려진 결함을 수정하고 전체 동작을 다시 검토한다.
- [ ] 신체·투구·손·발·무기·방패의 크기와 연결 위치를 확인하고, 회전·원근 단축·가림을 관찰 기록에 구분한다.
- [ ] 재생성한 원본의 해시에 맞는 새로운 독립 관찰 파일을 작성한다.

### P1. 시간에 따른 품질 검증 추가

- [ ] 골격 모션 검사와 생성된 2D 움직임의 검토 결과를 구분해 보고한다.
- [ ] 접지·발 미끄러짐·지면 관통·인접 프레임 및 마지막→처음 연결의 문제를 검출하는 검증을 추가한다.
- [ ] 보행 결함을 넣은 사례로 회귀 검증하고, 정상 뼈 길이와 픽셀 규격만으로 자연스러운 걷기를 PASS 처리하지 않는다.
- [ ] 측정하지 못한 항목과 검토 필요 항목을 보고서에 드러낸다. 자동 지표와 시각 판단을 각각 기록한다.

### 완성 에셋 승인 조건

- [ ] 선언한 도트 규격·공통 팔레트·알파 검사가 PASS다.
- [ ] 고정된 신체 비율·카메라·포즈와 관찰 가능한 부위 크기를 검증하고, 미해결 FAIL/REVIEW를 해소하거나 검토 근거를 기록한다.
- [ ] 걷기에는 체중 이동·접지·반복 연결이 읽히고, 공격·막기는 준비·실행·회복이 자연스럽게 이어진다.
- [ ] 깨끗한 GIF, 골격 GIF, 프레임 시트, 실제 격자·같은 영역 확대를 함께 검토한다.
- [ ] 검토자·대상 파일 해시·남은 한계를 포함해 작화 승인 여부를 명시한다. 사람 승인은 실제 사용자 승인에 근거해서만 기록한다.
