# 스프라이트·애니메이션 요구사항과 진행 상황

갱신일: 2026-10-22. 작업 브랜치 `codex/design-first-sprites`, [PR #10](https://github.com/jungducknam/pixelwright/pull/10)은 초안·미머지 상태입니다. 기준 main은 `1899f66`입니다.

현재 구현 추적은 [#13 — 3D 골격 없이 임의 객체의 스프라이트 생성과 일관성·동작 검증 도구 추가](https://github.com/jungducknam/pixelwright/issues/13)에서 진행합니다. [#12](https://github.com/jungducknam/pixelwright/issues/12)는 기존 기사 초안의 보행·작화 결함을 보존합니다.

**최신 목표는 골격을 필수로 만들지 않고, 임의 물체의 움직이는 부위와 이미지 크기·색·비율·디자인을 일관되게 생성·검증하는 도구를 제공하는 것입니다.** 실제로 존재하지 않는 물체에 해부 구조를 설명해야 하는 문제를 없앱니다. 3D 골격은 필요할 때 선택하는 보조 경로입니다.

## 1. 요구사항 변경 이력

1. 스프라이트와 걷기·공격·막기를 실제 생성하고 검증한다.
2. 3D 구도로 2D 도트를 만들되 부위 크기·동작 규모·도트 품질을 유지한다. sprite-gen의 공유 시안·상태별 시트 방식을 참고한다.
3. 3D 외형을 그대로 베끼지 않는다. 참고 이미지나 프롬프트로 2D 시안을 먼저 선택하고 그 외형을 모든 상태에서 유지한다.
4. 기사 걷기 GIF가 부자연스럽다는 피드백을 받았다. 기존 검사 PASS가 자연스러움의 증거는 아니며 접지·체중 이동·연결을 다시 검토해야 한다.
5. **최신 변경:** 3D 스켈레톤 생성 의무를 없앤다. 부위는 사용자가 물체에 맞게 이름 붙이고, 실제 2D 그림에서 관찰한 마스크·특징점·치수로 일관성과 움직임을 검사한다.

3D 필수로 작성됐던 이전 요구사항과 상세 결함은 [변경 전 기록](SPRITE_REQUIREMENTS_AND_STATUS_3D_HISTORY_ko.md)에 그대로 보존했습니다. 최신 기본 경로에는 그 문서의 필수 3D 조건을 적용하지 않습니다.

## 2. 현재 기본 흐름

```text
참고 이미지 또는 프롬프트 → 2D 도트 시안 선택
  → 물체에 맞는 부위·특징점, 규격·팔레트·동작·시간·허용치 고정
  → 같은 시안과 상태별 프롬프트로 새로운 2D 스프라이트 시트 생성
  → 원본 보존 및 선언한 전체 캔버스 파생 변환
  → 실제 픽셀의 부위·치수·특징점 독립 관찰
  → 픽셀·일관성·상대 움직임·연결·시간·선택적 접지 검사
  → 깨끗한 시트·GIF·격자·관찰 오버레이 확인과 작화 검토 기록
```

[실행 절차](SPRITE_2D_ko.md), [설치 도구 명세](../pixelwright/references/sequences.md), [검증 기록](VALIDATION_sequences_ko.md)을 제공합니다.

## 3. 요구사항과 수락 기준

| ID | 요구사항 | 수락 기준 |
| --- | --- | --- |
| R01 | 2D 시안을 먼저 선택한다. | 이후 모든 상태가 같은 선택 시안과 고정 팔레트를 참조한다. 시안 선택은 최종 작화 승인이 아니다. |
| R02 | 필수 스켈레톤과 사람 해부 용어를 없앤다. | 임의 부위·특징점을 사용하는 비인간형 예제를 Blender·3D 입력 없이 설치된 도구로 실행한다. |
| R03 | 부위가 실제로 움직이고 연결을 유지한다. | 관찰한 특징점의 필요 이동량, 연결 거리와 허용 길이를 검사한다. `relative_to`로 전체 이동과 부위의 상대 움직임을 구분한다. |
| R04 | 크기·비율·색·디자인을 일관되게 유지한다. | 고정 슬롯·배율·팔레트, 가시 면적, 관찰 치수·상대 비율, 색 분포·형상·색 무늬를 시안과 비교한다. |
| R05 | 도트 품질을 준수한다. | 최종 정사각형 셀 내부의 정확한 RGBA·정수 확대·알파·팔레트를 검사한다. 원본 격자와 손실 파생 변환을 구분하고 윤곽·클러스터·가독성은 별도 검토한다. |
| R06 | 새 동작을 시트로 그린다. | 상태별 의도·프레임 설명·시간·반복 여부를 사전 고정한다. 프레임별 확대·축소·크롭·중심 맞추기로 실패를 감추지 않는다. |
| R07 | 시간에 따른 결함을 검사한다. | 인접 프레임·반복 경계의 시간 기반 속도, 선택적 가속도·접점 미끄럼·지면 높이를 검사한다. 원래 기사 걷기는 별도 개선 대상이다. |
| R08 | 실제 그림을 독립적으로 관찰한다. | 원본·시안·계약 해시에 관찰을 묶는다. 좌표 가이드 복사나 기대 좌표를 정답으로 쓰지 않으며, 가림·미관찰은 REVIEW다. |
| R09 | 실패와 재생성 이력을 보존한다. | 시안·명세·프롬프트·원본·해시·파생 변환·검사·GIF를 보존한다. 교체 원본과 생성 기록을 보관하고 새 그림은 다시 관찰한다. |
| R10 | 기술 규격과 완성 작화를 구분한다. | 픽셀만 PASS인 미관찰 결과는 전체 REVIEW, 동작·일관성 위반은 FAIL이다. 검토자·근거·오차를 명시하며 실제 사용자 승인 없이 사람 승인을 기록하지 않는다. |
| R11 | 설치 후 동일하게 실행한다. | 설치 ZIP에 실행 스크립트·참조 문서·비인간형 튜토리얼을 넣고 독립 설치에서 정상·결함·미관찰·이력 검증을 실행한다. |

## 4. 구현 현황

| 항목 | 현재 상태와 한계 |
| --- | --- |
| 기본 도구 | [`pixel_sequence.py`](../pixelwright/scripts/pixel_sequence.py)의 prepare/import/generate/observations/check 구현. 기존 3D 도구는 선택적 경로로 유지한다. |
| 외형·입력 고정 | 시안·팔레트·명세·상태 프롬프트 해시 확인, 명시적 교체와 원본·생성 이력 보존 구현. |
| 임의 부위 검사 | 실제 부위 마스크·측정 끝점·특징점 관찰, 시안 대비 면적·색·무늬·치수·비율 비교 구현. 자동 의미론적 분할은 제공하지 않는다. |
| 동작 검사 | 필요한 이동량, 관찰 특징점에 대한 상대 움직임, 프레임 시간·반복 경계, 선택적 가속도·연결·접지 구현. 자연스러움 자체는 시각 검토가 필요하다. |
| 독립 튜토리얼 | 직접 작성한 가상 부유 장치의 셀을 사용한다. 이미지 생성 결과로 소개하지 않으며 변경된 그림에 기존 관찰을 재사용하지 못한다. |
| 실제 생성 | Aetherseed 시안·부유 시트를 호스트 image_gen 2회로 생성. 3D 입력 없음. 모델 식별자는 호스트에 노출되지 않는다. |
| 실제 예제 결과 | 파생 PNG 픽셀 PASS, 미관찰 전체 REVIEW. 보조 관찰 후 전체 FAIL: 기준 이탈 65건·검토 1건·정보 1건. 단순 지표의 이탈 개수이며 확정 작화 결함 개수가 아니다. |
| 실제 작화 | Aetherseed `changes_needed`, 사용자 승인 없음. 부위 경계의 약 1셀 관찰 오차와 1.5셀 이내 특징점 보정을 명시한다. |
| HTTP 생성 래퍼 | 선택 시안 한 장과 고정 프롬프트의 전송·오류 보존은 모의 응답으로 검증한다. 이번 실제 생성은 호스트 도구를 사용했고 유료 HTTP 실호출 검증은 아니다. |
| 테스트·설치 검증 | 로컬 전체 292개 테스트 PASS. 설치 ZIP 46개 파일의 무결성, 독립 설치의 정상·미관찰·고정 동작·GIF·이력·오래된 관찰 검증 PASS. [검증 기록](VALIDATION_sequences_ko.md) 참조. 버전 표시는 0.6.2를 유지하며 별도 릴리스는 발행하지 않았다. |

실제 결과: [원본·관찰·검사·GIF](examples/aetherseed-2d/). 이전 3D 기사 초안의 18프레임은 **4 PASS / 13 FAIL / 1 REVIEW**이며 자연스러운 걷기는 미완성입니다. 새 검사기를 구현했다고 기존 기사가 수정되거나 승인된 것은 아닙니다.

2026-10-22 후속 실행: [새 도구로 생성한 8프레임 기사 걷기](examples/knight-walk-2d/)를 호스트 image_gen 3회로 제작하고 실제 픽셀을 독립 관찰했습니다. 세 번째 파생본의 픽셀·전체 면적 검사는 PASS지만, 근거리/원거리 발 접지 미끄럼은 14.0/15.3셀(허용 2셀), 벨트 상하 변화는 약 1셀입니다. 전체 기준 이탈 88건·검토 17건·정보 1건, 작화 `changes_needed`로 **보행 개선 완료는 FAIL**입니다. 7→0 특징점 속도 제한은 통과해도 지지발 교대와 자연스러움을 승인하지 않습니다. 원본·계약·프롬프트·관찰·GIF와 수정 이력을 보존했고 수락 기준은 완화하지 않았습니다.

## 5. 남은 작업과 완성 작화 승인

- [ ] 기사 걷기의 접지·체중 이동·팔·장비 연동·반복 경계를 새 실행에서 개선하고 실제 관찰로 재검증한다.
- [ ] 기존 공격의 메이스 크기·웅크림, 막기의 방패 위치 결함을 수정한다.
- [ ] Aetherseed의 색·무늬·부위 크기·움직임 기준 이탈을 검토하고 같은 계약으로 필요한 상태를 다시 그린다.
- [ ] 자동 관찰기를 연결할 경우 실제 픽셀에 대한 의미 정확도와 가림·불확실성을 별도 검증한다. 현재는 관찰 입력을 받는 방식이다.
- [ ] 생성된 완성 에셋의 윤곽·색 뭉침·명암·자연스러움·무게감·동작 의도를 검토하고 실제 사용자 승인을 기록한다.

도구 구현 완료와 예제 작화 완성은 서로 다른 상태입니다. 이번 범위는 범용 생성·검증 도구, 문서·예제·이슈·패키지 검증과 브랜치 푸시입니다. 기존 작화 결함과 main 머지는 이 범위에서 완료로 처리하지 않습니다.
