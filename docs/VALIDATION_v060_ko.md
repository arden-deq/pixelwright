# Pixelwright v0.6.0 스프라이트·애니메이션·부위 리그 검증 기록

검증일: **2026-10-21**. Linux 컨테이너에서 아래 세 환경으로 실행했습니다. Windows에서는 이번에 직접 실행하지 않았으므로, 저장소 [CI](../.github/workflows/ci.yml)의 Windows Python 3.12·3.14 작업 결과를 따로 확인해야 합니다. 실제 Claude 계정 설치·업로드는 포함하지 않았습니다.

기존 140개 테스트에 스프라이트 테스트 33개를 더했습니다. Linux에서는 Windows 심볼릭 링크 권한 때문에 건너뛰던 두 테스트도 실행돼 건너뛴 테스트가 없습니다. Skill 형식 검사(skill-creator `quick_validate.py`)와 `git diff --check`도 통과했습니다. Pillow 13.0.0 결과는 열려 있는 의존성 갱신 제안을 판단하는 근거로도 쓸 수 있습니다.

## 새 테스트가 확인하는 것

테스트 시트는 생성기를 쓰지 않고 RGBA 셀과 NumPy 반복으로 직접 만듭니다. 각 리그 테스트는 일관된 2프레임 동작(고정 바닥, 회전축으로 1칸 이동하는 상자, 90° 회전하는 팔)에서 성질 하나만 바꾸고 해당 오류 코드를 기대합니다.

- 배치 계산, 투명 여백을 둔 시트 빌드, 팔레트 라이브러리 재사용, 잘못된 프레임 크기 거부
- 시트 전체 검사 실패 시 프레임·리그 검사 중단, 여백·빈 슬롯·가장자리 여백 위반, 빈 프레임, 명세 색상 행렬과 다른 시트
- 부위 맵과 도트 불일치, 고정·단단한 부위 변경, 회전축과 다르게 움직인 도트, 이동 축 위반
- 뼈대를 벗어난 도트, 뼈 길이 변화, 두꺼워진 부위의 면적, 옆으로 밀린 부위의 이탈
- 앞에 그려진 부위가 있을 때만 허용되는 가려짐, 프레임별 깊이 덮어쓰기, 앞 부위를 거친 부모 연결
- 고정 관절, 반복 애니메이션의 마지막→첫 프레임을 포함한 관절 이동 상한, 새 색상 검토
- 명세 오류 35종, 중복 JSON 키와 NaN, CLI 종료 코드, 입력 보존, 동봉 예제의 바이트 단위 재생성

테스트가 실제로 규칙을 지키는지 확인하려고 엔진 규칙을 일부러 끈 상태로도 실행했습니다. 깊이 기반 가림 처리를 끄면 5개, 이탈 판정을 끄면 2개, 회전축 불일치 판정을 끄면 1개, 위치 매칭을 무한히 느슨하게 하면 6개 테스트가 실패했습니다.

걷기 예제의 부위·프레임 비교 64건은 모두 통과했습니다. 뼈 부위의 형태 일치는 97.1~100%, 면적 비율은 0.85~1.12배, 뼈 기준 이탈은 최대 0.67칸입니다. 머리는 몸통이 위아래로 움직이는 동안 정확한 복사본을 유지했고, 몸통에 완전히 가려진 프레임의 뒤팔은 `hidden`으로 기록했습니다. 레버 손잡이는 받침과 손잡이공에 양 끝이 가려진 상태에서 형태 일치 100%, 면적 0.95~1.00배였습니다.

두 예제는 [`tools/generate_sprite_examples.py`](../tools/generate_sprite_examples.py)가 선언한 골격에서 부위를 그려 만든 것입니다. 그래서 통과 자체는 구성상 예상된 결과이며, 손으로 그린 애니메이션에서의 오탐률을 보여 주지는 않습니다. 실제 결과물은 [스프라이트 예제 기록](examples/sprites/)에 있습니다.

## 오류 주입 시험

통과한 두 예제에 실제로 흔한 실수를 하나씩 넣고 검사했습니다. 11건 중 9건을 검출했습니다.

| 주입한 실수 | 결과 | 주요 코드 |
| --- | --- | --- |
| 5번 프레임 앞팔 도트를 뼈대에서 3칸 옮김 | 검출 | `PART_OFF_SKELETON` 61%, `PART_DRIFT` 2.90칸, `JOINT_OFF_PART` |
| 6번 프레임 머리 한 픽셀 색 변경 | 검출 | `RIGID_PART_CHANGED` |
| 3번 프레임 목 관절은 두고 머리만 1칸 위로 | 검출 | `PART_JOINT_MISMATCH` |
| 2번 프레임 정강이를 한 칸 두껍게 | **미검출** | 면적 1.14배로 기본 허용 범위(0.75~1.25배) 안 |
| 4번 프레임 무릎 관절을 3칸 잘못 찍음 | 검출 | `BONE_LENGTH_CHANGED`, `JOINT_OFF_PART`, 허벅지 `PART_DRIFT` 1.70칸 |
| 1번 프레임 앞팔을 부위 맵에서 몸통으로 칠함 | 검출 | `PART_MISSING`, 연쇄된 `JOINT_OFF_PART`·`PART_AREA_CHANGED` |
| 6번 프레임 정강이를 옆으로 3칸 옮김 | 검출 | `PART_OFF_SKELETON` 78~79%, `PART_DRIFT` 1.96~2.01칸, `JOINT_OFF_PART` |
| 3번 프레임 레버 받침 1칸 이동 | 검출 | `FIXED_PART_CHANGED` |
| 2번 프레임 고정 축 관절 이동 | 검출 | `FIXED_JOINT_MOVED` |
| 1번 프레임 손잡이공이 손잡이 끝에서 벗어남 | 검출 | `PART_JOINT_MISMATCH` |
| 4번 프레임 손잡이를 옆으로 2칸 옮김 | **미검출** | 이탈 0.77칸, 면적 0.80배 |

손잡이 사례는 기준 프레임(수직)에서 손잡이가 받침과 손잡이공에 가려 20칸만 보이고, 4번 프레임에서도 16칸만 보여서 비교할 정보가 적었습니다. 역방향 사상 예측과 뼈 방향 범위를 맞춘 이탈 측정도 시험했지만 정상 범위(최대 0.36칸)와 확실히 구분하지 못해 채택하지 않았습니다. 임계값을 이 사례에 맞추지 않고 한계로 기록했습니다. 두께가 중요한 부위는 `area_tolerance`를 낮춥니다. 이 예제의 앞 정강이를 0.1로 낮추면 정상 시트는 그대로 통과하고 두꺼워진 정강이는 `PART_AREA_CHANGED`로 실패했습니다. 얇은 부위는 가장 많이 보이는 프레임을 기준으로 삼도록 안내합니다.

README의 실패 시연은 [같은 걷기 시트 픽셀](examples/sprites/walk-arm-lag/)을 4번 프레임에서 앞팔이 앞으로 흔들리는 골격으로 검사한 결과입니다. 시트 SHA-256은 통과한 걷기 시트와 같고, 팔 도트가 골격을 따라가지 않아 `PART_OFF_SKELETON`(70%), `PART_DRIFT`(2.10칸), `JOINT_OFF_PART`(2.4칸)로 실패합니다.

## 설치 ZIP 실행

`verify_release.py`는 설치 ZIP을 풀어 두 예제를 빌드·검사하고, 빌드 기록의 해시가 실제 시트와 같은지, 리그·배치 미리보기와 애니메이션 GIF가 생성되는지, 동봉 입력이 바뀌지 않는지 확인합니다. 이어서 레버 명세의 1번 프레임 손잡이 끝 관절만 1칸 옮긴 사본을 같은 시트로 검사해, 손잡이공의 `PART_JOINT_MISMATCH`와 종료 코드 `2`를 확인합니다. 기존 팔레트·레이어·격자 간격 검증도 그대로 통과했습니다.

```sh
python -m unittest discover -s pixelwright/tests
python tools/package_skill.py --out-dir dist
python tools/package_skill.py --verify dist/pixelwright-v0.6.0.zip
python tools/verify_release.py --archive dist/pixelwright-v0.6.0.zip --out-dir runs/release-v060-check-v1
```

## 남은 확인

- Windows CI 작업의 실제 결과
- 손으로 그린 걷기·공격·사물 애니메이션을 모은 평가 세트에서의 오탐·미검출률과 기본 허용치 재조정
- 기존 시트에 부위 맵을 주석으로 붙이는 작업량. 프레임 행렬과 빈 부위 맵을 뽑아 주는 보조 명령은 다음 단계 후보입니다.

기술 PASS는 선언한 부위가 선언한 골격과 일관된다는 뜻입니다. 동작의 타이밍·무게감·실루엣·매력은 미리보기를 보며 따로 검수합니다.
