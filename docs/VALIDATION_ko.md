## 독립 사용 검증

검증 에이전트에게 구현 결론을 전달하지 않고 Skill 경로와 다음 작업만 제공했습니다.

- 12×16 논리 캔버스의 포션 아이콘, 배율 6, 보이는 RGB 최대 8색, binary alpha.
- 원본 키트의 `strict_grid_demo/broken.png`를 32×48 논리 캔버스·배율 8로 검사하고 보정하지 않기.

포션은 저장된 네이티브 PNG가 12×16, 확대본이 72×96이며 192개 셀 전체가 단색입니다. 독립적인 Pillow/NumPy 비교도 네이티브 샘플이 정확히 6×6으로 반복됨을 확인했습니다. 보이는 RGB는 8색, 알파는 0과 255뿐입니다. 에이전트가 실제 출력과 미리보기를 보고 실루엣·코르크·액체 표현도 검토했습니다. 이 관찰은 객관적인 미학 보장으로 취급하지 않습니다.

기존 불량 샘플은 256×384의 기하를 충족하지만 `(16,13)`, `(26,22)`, `(12,35)` 셀에서 정확한 RGBA 차이를 검출했습니다. 평균 점수는 99.9969였으나 엄격한 판정은 FAIL입니다. 부분 알파 샘플도 1개 발견했습니다. 입력 SHA-256은 검사 전후 동일했습니다.

## README 기사 비교 자료

기존 공개 자료 화면을 실제로 생성하고 사용자가 확인한 기사 두 버전으로 교체했습니다. 두 버전 모두 출력은 1024×1536으로 유지하고, 도트 크기만 4×4에서 8×8로 바꾸면서 논리 원본을 256×384에서 128×192로 변경했습니다. 두 규격의 총 122,880개 셀이 모두 단색이며, 가시 색상 31개와 투명색 1개로 이루어진 동일한 팔레트를 사용합니다.

[`docs/examples/knight/`](examples/knight/)에는 재현 가능한 논리 행렬, 프로필, 원본·출력 PNG, 실제 검사 보고서와 파일 해시를 보관했습니다. 검사기와 별도로 PNG를 디코딩해 각 논리 샘플이 정확히 4×4 또는 8×8로 반복되는지 비교했습니다. README의 확대 컷은 두 버전에서 같은 이미지 좌표를 같은 표시 배율로 보여 주며, 전체 격자 미리보기는 모든 셀 경계를 표시합니다.

이 기록은 검사한 두 조건에서 같은 기술적 품질 규칙을 충족한 근거입니다. 도트가 커지면서 묘사가 간결해지는 변화와 미적 품질은 별도의 시각 검수 대상입니다.

## README 헤더 배너

내장 이미지 생성 도구로 만든 소개 배너는 원본이 1774×887이라 선언한 2048×1024·4 px 규격에서 기하 FAIL이었습니다. 원본을 보존하고 별도 캔버스 준비·격자 투영·32색 논리 행렬·정수 배율 렌더링을 거쳐 최종 PNG를 검사했습니다. 최종 결과는 131,072개 셀이 모두 정확한 단색이며, 반투명 샘플과 팔레트 밖 색상은 0개입니다. PNG와 프로필 해시를 보고서에 기록했습니다.

제작 프롬프트, 원본 FAIL 보고서, 최종 PASS 보고서, 편집 가능한 행렬, 검사기가 만든 격자 미리보기는 [헤더 제작 기록](examples/header/README.md)에 있습니다. 미리보기의 수직 참고선은 두 셀마다 표시하지만, 실제 검사는 모든 4×4 셀을 포함합니다. 제목·문구·기사·아이템·아이콘은 최종 PNG를 눈으로 확인했습니다.

사용자 요청에 따라 배너 내부의 확대창·연결선·선택 마커를 내장 이미지 편집기로 제거했습니다. 기존 32색 팔레트와 출력·격자 규격을 유지해 재내보낸 수정본도 131,072개 셀 전체 PASS입니다. 별도 검사 미리보기와 보고서는 수정본으로 갱신했습니다.

## 재실행

저장소 루트에서:

```sh
python -m unittest discover -s pixelwright/tests -v
python tools/package_skill.py --out-dir dist
python tools/package_skill.py --verify dist/pixelwright-v0.3.0.zip
python tools/verify_release.py --archive dist/pixelwright-v0.3.0.zip --out-dir .work/release-check-new
```

출력 폴더에는 실행별로 새 이름을 지정합니다. 단순 반복 실행의 산출물 덮어쓰기는 거부됩니다. `verify_release.py`는 설치 ZIP에서 빌드·감사를 실행하고 정상/불량 판정과 원본 보호를 확인합니다.
