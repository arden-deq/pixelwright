# Pixelwright 개발 판단과 v0.3.0 구현

사용자가 제공한 `pixel-art-qa-development-kit-v0.2.0 (1).zip`을 출발점으로 삼았습니다. 압축 파일의 지시문·로드맵은 검토 대상 자료입니다. 사용자의 목표는 GPT/Claude 공통 지원, Pixelwright 이름, 생성 전후의 균일한 픽셀 규격이며, 첫 대상은 정적 PNG입니다.

## 보장 범위를 생성 구조로 옮기기

기존 키트는 이미 잘못 만들어진 이미지의 문제를 찾는 검사기에 가까웠습니다. 픽셀아트 프롬프트를 강화해도 생성 모델의 출력은 사각형의 크기나 내부 RGBA가 일정하지 않을 수 있습니다. 새 생성 경로는 AI가 논리 색상 행렬을 작성하고, 결정적 렌더러가 각 셀을 하나의 색상으로 채워 정수 배율로 확대합니다. 렌더된 파일은 별도 검사기에 다시 넣습니다.

논리 캔버스가 `16×16`, 배율이 `8`이면 파일은 `128×128`, 모든 셀은 `8×8`입니다. 원본의 모든 셀에 같은 규칙을 적용합니다. 붙어 있는 같은 색상 셀들이 긴 직사각형·계단 형태가 되는 것은 정상입니다. 셀 규격과 클러스터 모양을 혼동하면 정상 그림을 잘못 거부하게 됩니다.

실루엣과 색상 설계 같은 미적 품질은 수학적으로 보장되지 않습니다. Skill은 내보낸 실제 그림을 보여 주고 논리 해상도에서 검수하도록 안내합니다. 일반 생성 모델 결과도 사용할 수 있지만 최초 상태는 미검증 후보이며, 격자 투영 결과는 새 파생 이미지로 기록합니다.

## 기존 키트에서 보강한 부분

| 항목 | v0.2.0의 한계 | v0.3.0 |
| --- | --- | --- |
| 생성 단계 | 생성 프롬프트와 후검사 중심 | 팔레트·논리 행렬에서 정확한 PNG 생성 |
| 규격 재사용 | 이미지마다 CLI 옵션 지정 | 엄격한 JSON 프로필 및 배치 검사 |
| 투명색 | 알파 0 RGB를 항상 무시 | 기본 exact, 선택적 visible 정책 |
| 팔레트 예산 | 대표색 미리보기의 색상 수 검사 | 실제 입력의 보이는 RGB 색상 수 검사 |
| 오류 표시 | tolerance 때문에 정확한 결함이 가려질 수 있음 | 정확한 결함 표시와 전체 논리 마스크 |
| 원본 보존 | 출력 파일명 충돌 가능 | 비어 있는 새 출력 폴더와 충돌 검사 |
| 파일 범위 | 다른 포맷·애니메이션 첫 프레임을 암묵 변환 | 정적·손실 없이 RGBA8로 해독 가능한 PNG만 허용 |
| 추적 | 파일과 검사 결과 연결이 약함 | 원본·프로필·생성 명세·출력 SHA-256 |
| 보정 판정 | 종료 코드와 검사 상태 의미가 불일치 | 원본과 보정 후 보고서 분리, 최종 후보 기준 종료 |
| 크기 제한 | 큰 네이티브 이미지 미리보기가 과도하게 확대됨 | 미리보기 확대량 제한 |
| 플랫폼 | ImageGen에 결합된 지시 | 공통 Skill + 실행 가능 여부에 따른 경로 |

`schema_version: 1`은 프로필과 새 보고서 구조의 버전입니다. 패키지 버전은 `0.3.0`입니다. 기존 `pixel_qa.py inspect/fix` CLI를 유지했지만 투명색 기본 정책, 팔레트 판정, 비어 있는 출력 폴더 요구, 보정 종료 코드가 바뀌었습니다. v0.2 결과와 비교할 때 설정을 확인해야 합니다.

## 검증 전략

기존 19개 회귀 테스트를 먼저 통과시킨 뒤, 새 동작을 별도 검증합니다. 한 물리 샘플의 색상·알파 차이, 오프셋 격자, 직사각형 셀, 비정수 확대, 보이지 않는 RGB, 팔레트 밖 샘플, 애니메이션·포맷 거부, 원본 보호가 핵심 사례입니다.

생성기 테스트는 내보낸 PNG를 다시 열어 각 블록이 원래 논리 셀과 정확히 같은지 확인합니다. 배치 테스트는 손상된 파일이 있어도 나머지 항목을 검사하고, 중복 파일명으로 산출물이 충돌하지 않는지 확인합니다. 독립 에이전트는 Skill만 읽고 실제 요청을 실행해 안내와 산출물의 연결을 점검합니다. 플랫폼 호환성은 공식 문서에 근거한 패키지 설계이며, Claude 계정에서 실제 설치·실행한 결과와는 구분합니다.

## 다음 단계의 우선순위

1. **실사용 평가 세트:** 캐릭터·아이템·UI에서 생성 모델별 후보를 수집하고, 구조 PASS와 시각 승인율·수정 시간·중요 디테일 손실을 따로 기록합니다. AI가 임의로 붙인 미학 점수는 합격 근거로 삼지 않습니다.
2. **편집 가능한 논리 데이터:** 지정한 좌표·색상·구역을 행렬에서 수정하는 보조 명령, 공통 팔레트와 색상 램프 관리. 사용자의 실제 수정 패턴을 확인한 뒤 추가합니다.
3. **영역·아틀라스 계약:** padding, frame origin, frame dimensions를 명시하고, 프레임별 검사와 세트 공통 팔레트·도트 크기 검사를 확장합니다. 현재 임의 크롭·애니메이션 판정을 제공하지 않습니다.
4. **선택적 미리보기 UI:** 실패 셀 확대·좌표 선택과 원본/보정 비교. 정확한 검사 엔진과 보고서 계약이 먼저 안정화되어야 합니다.

이미지 생성 API 연결, Aseprite 연동, 자동 미학 채점, 완전 자동 채택은 이번 버전에 포함되지 않습니다. 구조 검사를 통과시키기 위해 논리 해상도를 뒤늦게 바꾸는 기능은 추가하지 않습니다.
